# Agent Note: 管理员拥有的网页搜索上限

Status: implemented

[English](2026-09-19-admin-owned-web-search-limits.md) | 中文

## Problem

搜索量与并发度固定在面向模型的工具配置中。管理员没有产品界面来限制结果上下文、多查询扇出或 SearXNG 总压力。如果把这些控制交给模型，资源策略将取决于提示词，并扩大工具 schema。分页还会为可由一次有界响应满足的用例增加模型轮次和保留的提示指引。

## Decision

`dsh-web` 拥有实时 `web-search` settings 命名空间，包含四个正整数字段：合并结果上限 12、每次工具调用最多 4 个查询、整个 Host 最多同时运行 4 个提供方请求，以及 30,000 毫秒的搜索预算。`dsh-tool-web` 在注册 Agent 的搜索工具时捕获结果/查询上限和预算。工具 schema 仍然只有 `queries`；没有页码、结果数或并发度参数。

Host 并发门是所有会话与 Agent 共享的 FIFO 队列。因为调用者的取消信号覆盖获取槽位与提供方执行，排队等待会消耗现有的工具调用预算。已取消的等待者会被移除。并发上限变更会控制后续准入，不会中断正在运行的请求。

插件配置页在提供方专用的 **SearXNG** 卡片旁以 **网页搜索** 卡片展示这些字段。搜索输出总会在返回的来源后提示模型：若查询结果不相关、过宽或不足，应修正查询，而不是原样重复。该建议属于每次结果，不放入系统提示词。搜索继续返回不带分页的 SearXNG JSON 摘要；完整页面仍由 `web_fetch` 负责。

## Alternatives considered

**向模型暴露结果数和分页。** 这会增加 schema 和提示复杂度，消耗额外轮次，并降低常规搜索的可预测性。管理员设定的单次结果集已足够；覆盖不佳时，模型可发出更好的查询。

**按会话或工具调用限制并发。** 会话与 Agent 增加时，独立上限会成倍增加后端流量。此策略旨在保护共享 SearXNG 实例，因此队列归 Host 服务所有。

**把查询修正建议保留在系统提示词中。** 该建议只在看到具体结果集后才有意义。将它与来源一起返回，可缩小常驻提示词，并把指引放在决策点。

## Consequences

- 管理员可在不扩大模型权限的情况下调整搜索上下文和共享后端压力。
- 多查询调用可并发执行提供方请求，但返回的来源不超过配置的合并上限。
- 已活动的工具定义保留捕获的结果/查询上限与超时；新挂载的工具使用当前 settings。Host 全局并发变更实时生效。
- SearXNG 默认语言为 `all`，提供方每次请求都会显式发送它。
- 聚焦的服务、工具、提供方、settings 卡片和 Web 场景测试覆盖默认值、校验、FIFO 准入、取消、提示词/schema 边界、输出建议、持久化与语言处理。
