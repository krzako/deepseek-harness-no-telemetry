# Agent Note: Route Session intent separately from portable transfer

Status: implemented

## Problem

Provider/model names do not distinguish fresh creation, persisted resume, and import into a different agent. A transfer implemented for each source/target driver pair would grow quadratically and could silently omit model-visible content or invoke a destination before the user reviews compatibility warnings.

## Decision

`AgentDriverRoute` identifies `create`, `resume`, or `import`. Fresh creation follows the current selector policy; resume carries the recorded driver when present; import names the destination driver. Factories and selectors declare their stable driver id, so the registry rejects an unavailable or mismatched required driver before constructing an external driver. Codex honors an explicit import target independently of its automatic-selection setting.

`ctx.agents.create()` carries that explicit import route through session preparation to driver selection. It requires `meta.importLineage` with the source Session, source driver, and transfer id; the header preserves this ancestry across resume without treating it as a fork-inherited prefix. The seed's recorded driver must match the selected destination; a conflict aborts before publication. Import still starts a new Session, while transfer preparation remains a separate obligation.

`prepareAgentTransfer()` calls the source driver's export port at a completed turn boundary, validates the complete canonical context and source identity, and compares the explicitly selected destination model with the destination port's declared capabilities at preview and commit. An unavailable selected model blocks commit; a different model requires acknowledgment and prevents forwarding the source-model private checkpoint. Its commit also refuses other blocking issues and unacknowledged warnings. Only the destination port receives the canonical context; a compatible private checkpoint is forwarded solely to its owner. The caller supplies a fresh destination Session id; the transfer creates one id for its lineage independently of the source's live driver. The destination port receives that lineage and the frozen model selection, and must persist the lineage when it creates the new Session. The destination invocation is memoized, including rejection, so a repeated commit cannot replay side effects. The destination port produces an import preparation; Session creation and publication remain a separate lifecycle transaction.

Every source port also projects archived facts through `exportArchivedContext()`. The caller supplies a detached Session and verified artifact reader; source implementations cannot substitute their live-session resolver or local attachment store. Standard and Codex reuse their ordinary projections, while `verifyArchivedAgentContext()` compares the complete canonical bundle and private snapshot and rejects Session mutation. This keeps source semantics inside the source driver without source/target-pair adapters. Archive validation can therefore run without old runtime files or destination side effects.

The standard driver's portable projection derives messages from the same durable events used by `Session.deriveMessages()`. It retains shadowed messages as history and uses the surface fold for the effective order after replacements. Request headers contribute the latest system instruction and model route. Both resident and streamed projections retain header import lineage in source metadata, so exporting an imported Session preserves its recorded ancestry. A subsequent transfer creates a new lineage pointing to that Session without overwriting the source ancestry. The projection rejects an open turn or compaction and content it cannot map; packaging attachment bytes and invoking export/import ports remain separate responsibilities.

The inverse standard projection validates the canonical context and returns ordered effective entries without creating a Session. Instruction entries remain distinct from conversation messages, attachment references require complete resolved records, and unsupported blocks or invalid tool roles fail before import. Fresh deterministic message ids identify target-side messages; the source context remains available to the later import transaction for provenance.

The standard source and target ports adapt those projections to the common transfer coordinator. The source resolves one complete Session; the target declares its current model catalog and returns unpublished inputs with the chosen model and lineage. The coordinator uses the same calls whether the source driver is standard or another agent, while Session creation and attachment-byte publication remain owned by a later transaction.

Destination capability lookup accepts an asynchronous catalog reader. The coordinator awaits it for preview and again for commit, and the standard target rechecks the selected model before producing its preparation. A mutable settings-backed catalog therefore needs no stale transfer cache.

The standard loop registers that pair for its own lifetime. Its target reads the current LLM provider catalogs and accepts transfer-local, already-resolved attachment references in the common import input. The coordinator snapshots those references with the reviewed transfer instead of making the long-lived port retain archive-specific state.

The standard source resolves a live completed Session or opens its stored log read-only after that Agent closes. A live Session is flushed through the Session store before the durable read. The stored log is reconstructed into a detached Session for projection; exporting never resumes the Agent or replays model and tool actions.

The agent registry stores a matched source/target port pair under one stable driver id. Registration rejects a port with another driver id or a duplicate pair and expires with its caller's effect. It also rejects a full-driver factory or selector until the matching pair is registered. Transfer lookup names the driver, not a source/target combination or model provider; until a driver registers a pair, lookup fails explicitly.

The standard seed builder groups prepared messages into balanced synthetic turns and steps, records paired historical tool calls and results without executing either, and verifies the seed through Session replay. It rejects orphan results and unresolved calls. Source instruction entries stay separate; a later import transaction must install them at their proper role or refuse publication rather than silently converting them to user messages.

System-prompt sections support `literal: true` so a destination can install imported instruction text without interpreting source `{{...}}` bytes as local prompt variables. Default sections retain strict interpolation. For standard → standard import, the seed builder accepts one plain-text system instruction, copies it into the initial request header for resume, and refuses developer or non-text instructions that the standard system role cannot represent.

The standard loop publishes the prepared same-driver seed through `ctx.agents.create()` with explicit route and header lineage. It registers the recorded system text as a complete literal section before any new turn and repeats that registration on resume. Prompt assembly runs before publication, so a competing complete section rejects the import instead of failing in the first new turn; old tool and model events remain data rather than executable work.

## Alternatives considered

**Infer operation from provider or existing turns.** A new imported Session may use a provider name shared by several agents, while settings may change between export and import. The operation and target must be explicit.

**Create one translator per driver pair.** Pair-specific translations have no common completeness check and make adding a third agent require new paths for every existing agent. Shared format validation and destination-only import keep the number of ports linear.

**Replace the source driver during a live turn.** A partially consumed inbox or tool result cannot be reconstructed as a completed portable checkpoint. The source keeps its identity; transfer uses a completed boundary and a distinct destination identity.

**Export only the visible transcript.** It loses tool correlation and messages shadowed by compaction. The portable projection retains both while naming the effective model-visible order separately.

**Infer the destination model from the source.** A target agent may not offer that route, and a user may intentionally select a different one. Explicit selection lets the common compatibility assessment reject an unavailable route before calling the destination and disclose loss of private-checkpoint fidelity.

Archive compatibility preview validates the complete source before consulting destination capabilities. This ordering prevents a corrupt archive from reaching destination preparation; preview never calls the import operation. The target port also owns authentication inspection: standard delegates to the LLM adapter and Codex to its gateway configuration. Archive preview reports local credential metadata separately from context fidelity, skips inspection for unavailable models, and rejects inspection failure or cancellation. Missing references remain visible requirements; provider-managed authentication is not a claim that a login works. Context compatibility and credential presence remain distinct from authorization, remote validity and workspace readiness, so the report cannot authorize publication or a new turn.

Workspace inspection remains read-only and separate from context compatibility. Its four-case decision uses observed directory presence and the verified snapshot declaration. Existing files require a separately confirmed application with recoverable backup; a missing workspace without a snapshot remains a context-only choice. Presence is not a content comparison, so the preview cannot claim matching workspace fidelity from an unchanged path or a source digest alone. Dangling links and access errors reject instead of becoming an apparent free destination; the write transaction must revalidate the observed state.

Snapshot comparison reports each declared file against the authorized destination using byte count and streamed SHA-256. Links and parent/type conflicts remain explicit instead of being followed or replaced. Per-file equality does not describe extra destination files, permissions or directory metadata, and does not upgrade workspace fidelity. The comparison is not a reservation against concurrent filesystem changes; snapshot application owns a fresh check and recoverable backup.

Snapshot staging uses the ZIP validator's sequential scan with awaited chunk writes. A consumer receives the completed private directory only after all payloads, including non-workspace data, match the captured manifest. Exclusive file creation detects local path collisions; failed validation, cancellation and consumer failure all close handles and remove staging. This separates temporary materialization from the later destination transaction without buffering entire files or exposing partially verified bytes as an imported workspace.

Export and import both check ordinary attachment metadata across all included logs before deduplication. Export keeps one reference map for the entire tree so a descendant cannot replace a conflicting root reference and produce an archive that its own importer rejects.

Portable export checks each included log twice: its initial flushed read supplies ZIP bytes, and a final flushed read must match the retained digest before the manifest is emitted. The descendant inventory must also match. The final checks start after all initial reads and context streams, so changes during collection reject instead of combining inconsistent observations in a completed archive. No lock is held after the verified read; later changes belong to a subsequent export.

Log-only ZIPs cannot establish a portable agent context. The validator reports a specific manifest-required error after container integrity checks rather than inferring context from a transcript. This chooses explicit refusal of faithful legacy import; a valid portable archive without a private checkpoint still proceeds to ordinary target compatibility assessment.

The Session header and `/export` share a browser-local plaintext warning. Opening it performs no network request; its primary action explicitly selects portable ZIP and its secondary action selects transcript-only log. Dismissing the warning grants no later download, while concurrent confirmations share an already-active operation. Each new operation requires a new choice; no acknowledgment is persisted in settings or Session history. This UI choice does not replace server authorization or implement encrypted archives.

Workspace fingerprints carry an algorithm identifier. The content algorithm hashes depth-first, code-unit-sorted JSON records for relative paths, directories, file lengths and SHA-256 values, and link text. It streams file bytes and rechecks observed filesystem identities and mutation metadata before returning. Missing, unreadable or unsupported trees produce explicit unavailability; partial-tree digests are never published. Legacy manifests remain accepted but their unversioned digests cannot prove equality. Matching content does not imply matching filesystem permissions or the full execution environment.

## Consequences

The transfer preview is read-only for the destination, and warnings require explicit acknowledgment before its port runs. The coordinator does not promise that a target preparation has become a durable DSH Session; the importer must commit that separate step and persist the supplied ancestry. Tests cover third-driver routing, private-state isolation, invalid source identity, active-turn rejection, required-driver mismatch, stable ancestry, and one-shot destination invocation.

The standard projection is a pure read of a completed Session, not a registered source port or an archive. Its tests cover tool correlation, system and route changes, surface replacement, attachment references, and explicit refusal of incomplete or unknown content.

The inverse projection is also preparation only. Tests cover attachment mismatch, unsupported content, malformed tool roles, deterministic ids, and export-to-import effective-history order without historical execution.

Standard-port tests cover completed-turn export, active-turn rejection, same-driver preparation, and cross-driver import through the same target port without pair-specific code.

Registry tests cover port identity, duplicate refusal, retrieval by driver id, effect-scoped removal, and rejection of full-driver registration before the pair is present. Driver-wide registration remains a separate composition step after the ports.

Seed tests cover replayed message order, balanced synthetic tool records and boundaries, separate instructions, and rejection of incomplete tool history.

HTTP export also defaults to portable when `format` is absent. Transcript-only export requires explicit `format=log`; missing durable driver selection or an unavailable source port returns 409 for both GET and HEAD rather than silently reducing archive fidelity.

HTTP preview uses Connection authentication and streaming request admission. It owns one private staging lifetime through validation and response construction, cleans it on every outcome, and returns only compatibility observations. Source-port resolution follows complete archive identity validation; no historical live Session resolver is used. This avoids publishing an import capability before transaction and authorization work is complete. Confirmation must reupload/revalidate rather than trust this report as a receipt.

Full-driver registration now requires a target publication capability alongside pure preparation. Archive orchestration can dispatch reviewed preparation through `target.createImportedAgent` without knowing its private type or selecting a driver-specific helper. The implementation stays with the destination driver and uses the existing shared factory; no pair adapter or second publication transaction is introduced. Pure standalone target ports remain usable for compatibility and projection tests.

Archive image restoration needs a storage capability separate from ordinary image admission. Re-running normalization can change bytes and hashes when destination policy or encoder versions differ, invalidating historical references. `AttachmentStore.restoreImage` retains exact archived bytes after digest, metadata and full-decode checks; local publication reuses the immutable-object commit and rejects unsupported backends. Current admission limits remain explicit refusal policy, not a reason to rewrite archived images.

`withDshArchiveAttachments` streams attachment payloads into exclusive private files and supplies an archive-path-to-file map only after revalidating every ZIP entry against the captured manifest. Empty attachments are preserved. It shares staging and cleanup with workspace extraction, applies operator limits to the whole archive, and removes partial or completed staging on failure, cancellation and success. The consumer owns store publication and cancellation after entry; it must not retain the paths. No Session, audit store or workspace is published by this helper. Inventories remain resident; payload writes use bounded chunks and backpressure. Archive attachment restoration and the encompassing import transaction remain separate work.

`restoreDshArchiveAttachments` restores logged images through exact `restoreImage` and streams generic files and referenced audit blobs through `saveFileStream` in 64 KiB chunks. It validates references and revalidates the entire archive before store calls, rejects changed provider references, and cleans staging and open handles on failure. One encoded image is resident at a time. Cancellation stops subsequent objects; already durable shared objects remain after partial failure and must not be deleted by import rollback. This helper does not publish historical events or Sessions and does not resolve canonical-only references or complete the enclosing workspace/import transaction.

Resolved transfer attachments use `portableAttachmentKey` (id, media type, optional name), not digest alone. This preserves identical bytes used as an image and a file or with several explicit filenames without overwriting references; the canonical archive format is unchanged. Archive resolution uses validated logged metadata, canonical image display names, and exactly one matching file reference. Missing metadata or an unnamed file with several candidates rejects explicitly. Resolution only prepares detached references; attachment restoration must finish before Session publication.

Transactional imports use `SessionPersistence.beginImport`: the write handle flushes durably while normal list/stat/open remain fenced. Unsupported providers reject before creating a Session. JSONL reserves a fresh identity under its kernel write lease and persists a pending visibility marker before log bytes; publication durably changes the marker, invokes the synchronous registry callback, and restores the fence if that callback fails. Only this fresh, uncommitted import may be rolled back; published imports and pre-existing generations cannot be removed by rollback. The Agent factory starts the driver with durable seed data before publication, disposes it on failure, and reports cleanup errors instead of swallowing them. An interrupted process leaves a hidden, reserved pending import, never an automatically resumed Session; automatic recovery or deletion of abandoned imports is not implemented. Normal rollback removes the uncommitted log and markers but retains the stable POSIX lock inode. Windows namespace changes use the existing write-through move primitive.
