# Agent Note: Measure portable Session archive entries before publishing a manifest

Status: implemented

## Problem

The [browser Session-log ZIP](../feature/2026-08-10-web-session-log-export.md) streams attachments without retaining their full bytes. A portable import needs a manifest with exact byte counts and SHA-256 digests for every included entry. Hashing only the declared attachment reference would not prove that the ZIP received those bytes, while buffering entire entries would defeat the streaming export.

## Decision

`measureDshArchiveEntry` wraps each ZIP entry and hashes the bytes as its consumer reads them. Text and resident binary entries receive immediate receipts; a streamed entry receives a receipt only after its iterator ends successfully. A shared optional budget rejects a chunk before emission if its entry or the complete uncompressed ZIP would exceed operator-configured byte limits; absent limits impose no archive-size policy. `portableJsonStream` serializes the canonical context and private checkpoint as bounded JSON chunks, preserving the bytes of `JSON.stringify` without a second whole-document string. `completeDshArchiveManifestV1` accepts only completed receipts and validates the final paths and required payload declarations against the versioned manifest contract. The explicit portable route obtains canonical context through the recorded driver's source port and rereads the root log before streaming; a changed log returns 409 instead of pairing it with a different context. The route accepts resident or streamed source bundles, and the default browser download remains manifest-free.

`validateDshSessionZip()` applies the inventory verifier to a completed private file before import. It uses yauzl's central-directory reader with lazy entries, strict filenames and size validation, then compares local headers and computes CRC32 and SHA-256 from decompressed bytes. Path sets reject duplicates and file/directory conflicts; file modes reject symlinks and other special files. A shared budget counts every uncompressed byte, including the manifest, with an optional entry-count bound. EOF, failure and cancellation close the ZIP and entry readers before settlement. The caller retains ownership of staging deletion and must keep the file stable throughout validation. The result proves container and inventory integrity, not payload semantics or import authorization.

`readDshSessionZipPayloads()` supplies resident preview inputs from selected declared paths. It snapshots the prior manifest, reruns the same complete container/inventory validation, buffers only selected payloads, and refuses a different manifest before returning the map. This prevents validation and semantic preview from silently observing different archives, including replacement with another internally valid ZIP. Unselected entries remain subject to hashes, CRC and operator limits. It creates no destination resources and leaves staging ownership with the caller.

`readDshSessionArchiveLogs()` validates all included logs with the installed format catalog after the verified payload read. Complete decoding rejects a corrupt tail rather than treating an archive as a crash-recovery source. The catalog restores current events and runs supported historical migrations in memory; stored versions remain available to preview. Duplicate Session identities, missing parents, inconsistent descendant depths and root/workspace disagreement reject the archive. Every non-root has an included parent with depth one lower, proving ancestry terminates at the declared root; the root may retain an external parent when exporting a subtree. This validates detached log data without invoking a driver or persistence writer. Canonical-context and attachment agreement remain separate requirements.

`readDshSessionArchiveBundle()` admits resident canonical metadata with the shared V1 validators and checks source identity, the complete driver-state value, the durable driver choice and recorded lineage against the restored root log. It rejects additional metadata declarations, invalid reference IDs in the canonical context and a private envelope owned by another driver. Its two payload reads compare against one captured manifest, preventing log and metadata reads from accepting different inventories. The same audit scanner serves export and preview: ordered facts require unique event IDs, one thread, completed compaction transitions and preceding receipts in their own Session. Preview checks each referenced blob against the verified manifest attachment path, SHA-256 and byte count. A receipt in another included Session cannot authorize that reference. Logged V2 checkpoints pass the existing Codex checkpoint verifier with their preceding audit facts and a resolver restricted to that log's referenced blobs. Each artifact read reverifies the ZIP against the captured manifest and buffers that artifact; repeated scans trade IO for avoiding an archive-wide payload cache. Checkpoint validation uses its private temporary spool and cleanup. Ordinary attachments use the exporter's carrier scanner over all decoded logs; conflicting metadata rejects before deduplication. References require matching manifest attachment paths and log byte counts, with SHA-256 agreement for content-addressed ids. Canonical references, including nested tool results and unnamed files, are checked against the same inventory. These checks do not decode images. Agreement between the private bundle and audited checkpoint, and complete source projection, remain separate checks; valid referenced bytes alone do not establish restore fidelity.

`prepareDshSessionArchiveImport` uses the validated archive bundle as the source of the common transfer preparation, so it never reads a live source Session. Review and commit share private captured data; the returned preview cannot mutate it. One memoized attempt restores durable attachments before preparing and publishing a new Session through the registered target port. Keeping an existing workspace is explicit and never applies archived snapshot files. Directory identity and the available fingerprint observation are rechecked before publication; no filesystem reservation is implied. Missing workspace without snapshot and replacement of an existing workspace remain explicit refusals. Factory import transactions own Session rollback; shared attachment objects and caller-owned archive staging have separate lifetimes. Authentication metadata is advisory for later model execution, not remote credential verification.

Snapshot directory metadata uses an optional complete `directories` inventory of archive paths under the workspace prefix. Its absence is retained as the legacy file-only case, not interpreted as an empty tree. Validation requires all parents, rejects file/directory conflicts and traversal, and staging reconstructs empty directories before checking any recognized full-content fingerprint. Only a snapshot with recorded directories can advertise conditional snapshot-content fidelity; legacy snapshots remain explicitly unverified. ZIP directory records do not establish this inventory because they are not included in the payload inventory and may be omitted by a writer.

Optional workspace export is selected by `includeWorkspace=true` only for portable archives. HTTP preflight captures the source-header workspace inventory; GET independently captures and streams it. All regular files, including hidden files, and all directories enter the snapshot without exclusions. Unsupported links, object types and paths reject explicitly. Shared stable file reads bound chunks and check identity before and after reading, while the final observation and fingerprint barrier rejects concurrent mutations before manifest completion. Operator byte budgets include workspace entries. The browser requires an explicit workspace download choice and warns about unredacted secrets. No destination workspace is changed by exporting or staging this archive.

Conflict preview includes every declared directory, including empty ones, and each file in `workspaceEntries`, with a `kind` discriminator. A file or link blocking a declared directory is a type conflict; a blocking ancestor is a parent conflict. `directory-present` records only the destination type and never establishes equality of directory contents. Legacy snapshots without directory metadata still compare their files. HTTP preview exposes the same report without modifying the destination; application and backup require a separate transaction.

New-workspace snapshot application uses the same coordinator and publisher after complete private ZIP staging. An exclusive root mkdir prevents adoption of destinations appearing after review; exclusive file creation and ordinary directory creation never overwrite existing files. Materialization compares full fingerprints before publication. Exception rollback validates ownership, identity and copied source prefixes before removing its tree; unknown edits or foreign files retain data and surface both primary and cleanup errors. Cancellation is checked before publication, not after a successful publisher returns. A durable sidecar intent precedes workspace creation and binds the fresh Session and import identity to the target and fingerprint. Materialized directory identity is recorded before publication; durable Session metadata proves completion without a fallible post-commit journal write. Recovery inspection and explicit retention preserve unknown effects and reject stale observations rather than deleting potentially edited data. Session/driver rollback belongs to the registered publisher. SIGKILL tests cover intent, materialization and published Session restart with a fresh backend; real browser composition checks the coordinator and publisher together. Windows workspace power-loss durability remains unverified. The coordinator returns the published handle with an independent staging-cleanup result because deleting private staging cannot undo Session publication. A cleanup failure preserves its path and cause without hiding the live handle; pre-publication failures retain both primary and cleanup errors. Real browser composition injects cleanup failure only after durable Session publication and checks that publication, workspace and lineage survive.

## Alternatives considered

**Trust attachment IDs as manifest hashes.** A file can fail during ZIP production after its reference was recorded, leaving a partial archive with a misleading manifest.

**Buffer each complete attachment before compression.** This would tie Host memory to the largest export file rather than to the compressor's bounded chunks.

**Read only streaming local headers.** They do not establish the central-directory inventory or expose all entry attributes. A maintained central-directory parser avoids implementing ZIP and ZIP64 parsing inside DSH.

## Consequences

The ZIP writer places the portable manifest last, after it has consumed and measured every entry. A partial or failed stream cannot yield a receipt, so it cannot enter a valid manifest. Every canonical-context attachment reference must match a measured archive entry, including references nested in tool results. Image paths omit the `sha256:` namespace prefix because colons are forbidden in portable ZIP paths; the shared path function serves both export and canonical reference checks, while durable ids remain unchanged. Each included Codex audit log rejects sequence gaps, reused event IDs, and unresolved compaction installation before the ZIP completes. A missing source port or mismatched Session identity rejects the portable request before streaming; tests pin exact UTF-8 and binary hashes, lazy chunk consumption, and rejection after interruption or read failure.

Recoverable content backups precede existing-workspace replacement. The internal backup helper owns a fresh private directory outside the source, records copying intent, copies ordinary files and empty directories, revalidates the captured source and durably records readiness. Binding the record to the import and Session avoids treating an unrelated backup as replacement authorization. A content fingerprint permits independent inspection after the writer exits or the source disappears. Partial copies remain inspection evidence, not ready backups. Links and special objects reject rather than producing incomplete recovery data. The helper does not itself replace files or claim ownership/ACL fidelity; the replacement coordinator consumes its ready output. Unit fault injection and a separate writer process cover source changes, cancellation, failed ready publication and detached verification.

Existing-path protection in workspace moves belongs to the native rename operation: checking ENOENT before ordinary rename leaves an overwrite race. The internal move helper uses [Linux RENAME_NOREPLACE](https://man7.org/linux/man-pages/man2/rename.2.html), [Apple RENAME_EXCL](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/rename.2), and [Windows MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw) without replacement or copy fallback. Missing symbols or filesystem support reject. POSIX parent-flush failure after success reports moved=true instead of claiming rollback; the enclosing transaction owns inspection. Native Linux tests cover files, empty/nonempty directories, links and post-move flush failure. Windows/macOS flag and error tests do not establish native execution or power-loss behavior.

Whole-tree replacement requires a separate commit acceptance from compatibility warnings. The coordinator captures source observations at review, creates and verifies a content backup, and records its binding in the import journal before moving paths. The original tree is retained inside that backup, preserving metadata unavailable to the content copy. No-replace moves protect competing destinations during installation and rollback. A failed publisher restores only an unchanged replacement; later edits retain both trees as outcome unknown. Successful Session publication owns completion, while retained backup and staging cleanup are separate result fields. The journal accepts historical records without backup metadata and requires matching Session/import identity when a backup is present. SIGKILL tests cover interrupted installation and post-publication inspection without deleting original data.

Archive HTTP access inherits the instance owner authentication and Host/Origin checks from Connection before format-specific parsing. Keeping this check in the carrier prevents a valid route or malformed ZIP from becoming an authentication bypass. Real application coverage exercises missing and invalid cookies, foreign Host/Origin and cross-site markers across GET/HEAD export modes and POST preview, with successful owner controls and no published Sessions or historical effects. This verifies current owner-scoped routes, not a multi-user ACL model or authorization for unimplemented import-commit/password operations.
