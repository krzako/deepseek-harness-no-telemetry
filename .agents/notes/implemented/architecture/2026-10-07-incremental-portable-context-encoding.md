# Agent Note: Incremental portable context encoding

Status: implemented

## Problem

The portable Session ZIP encodes a resident `PortableAgentContextV1` without forming one complete JSON string, but a large item array still occupies memory before ZIP emission. A future streaming source port needs the same canonical bytes and reference checks without retaining every item.

## Decision

`PortableAgentContextStreamV1` represents items, effective item IDs, and compactions as single-consumption async sequences beside the small source state. `PortableAgentStreamBundleV1` pairs this context with optional resident private state or a `PortablePrivateSnapshotStreamV1` whose source has validated the raw JSON context. `portableContextJsonStream()` encodes the V1 field order and validates each item, unique ID, effective reference, and compaction reference before the complete stream can receive a ZIP manifest receipt. `portableSessionZipEntries()` accepts either bundle form, validates streamed attachment references against completed ZIP receipts during item consumption, and rechecks streamed private-context length and SHA-256 before emitting a manifest. A named file reference must match the normalized ZIP name as well as its digest; an unnamed reference matches the digest. The context encoder retains identifier sets and only one snapshotted item or compaction at a time. The source port exposes an optional single-consumption export for the ZIP endpoint; import preview and drivers without that producer use the required resident export. The endpoint acquires the stream before its second durable-root read and consumes it only after the log consistency check. The standard driver projects ZIP items from a frozen Session event snapshot without a second resident item array.

`PortableOpaqueContextItemStreamV1` adds a transport-only representation for one opaque value. The source validates exactly one lossless JSON value before supplying its byte stream, size, and SHA-256; the archive encoder verifies that receipt at EOF, matching the existing private-checkpoint responsibility split. The on-disk item remains an ordinary V1 opaque block. JSON spelling inside the value is preserved, so whitespace and number notation may differ from resident serialization while parsed content is identical. Opaque values have no canonical attachment blocks; ordinary item attachment checks remain unchanged. The Codex compaction producer uses this representation for artifact prompts, results and failure details after complete JSON admission. Admission retains only the audited implementation and bounded scalar prefixes. The JSON parser owns syntax; UTF-8 decoding is fatal, and numeric admission preserves binary64 finite/nonnegative-zero checks using a bounded significant prefix and a sticky digit beyond all binary64 rounding boundaries. Failure wrappers are hashed over their message and full details with an additional verified read. Subsequent export reads recheck the artifact receipt.

## Alternatives considered

Changing the durable format to store opaque values as external references would require new import semantics. Transporting verified JSON bytes instead preserves the existing durable value and avoids a per-agent archive variant.

Encoding an entire array after the driver returns it retains the source-memory cost even when output chunks are bounded. Dropping reference validation until import would allow an apparently complete archive to contain missing or duplicate item identities.

## Consequences

For resident items the encoder reproduces `JSON.stringify` bytes for the same V1 object and rejects malformed data after partial output without yielding a complete measured entry receipt. Identifier sets still grow with the number of items and references, and a single large item is snapshotted before encoding. The standard driver retains its frozen Session event snapshot and reference sets. `codexPortableArtifactStream()` yields receipt-owned bytes with size/hash confirmation at EOF. `readCodexPortablePrivateSnapshotStream()` validates a V2 artifact and its audit from one such read, then offers a second digest-checked read for ZIP encoding; a concurrent Session append prevents publication. `withVerifiedCodexCheckpointArtifactV2()` exposes fields and array iterators only inside a callback while the validated private spool exists and removes that spool on completion or failure. `streamVerifiedCodexCheckpointArtifactV2()` starts the same validation on first iteration and retains the spool through the projected iterator; EOF, error, and cancellation remove it. `projectCodexEffectiveHistoryStream()` and `projectCodexHistoricalItemsStream()` project active and historical items with the resident path's ID and audited-outcome rules while retaining only compaction output references. `resolveCodexInstalledCompactionsWithStreamedHistory()` validates and yields one installed audit group at a time, consuming each attempt input history to receipt-verified EOF before retaining a fresh reader. This validates failed retries even though only the final successful input enters canonical ancestry. The final input is consumed again during projection; cancellation closes its iterator, and a read failure prevents publication of the relation. Artifact prompts, results, and failure details use admitted opaque streams; inline payloads remain resident. Artifact-backed context/config comparison consumes one property at a time and retains only seen and differing key sets, honoring the last duplicate value and verifying the receipt even after a mismatch. Checkpoint metadata and the largest property remain resident. The resident resolver keeps its array-based interface. `projectCodexCompactionAncestryStream()` projects each such group against its rollout output and yields its provenance items before reporting the canonical relation, without retaining all groups or items. `readCodexPortableStreamBundle()` composes them behind one completed Session fact read and emits the same parsed canonical context as the resident source for histories with and without compaction, preserving the raw JSON spelling of streamed opaque values. It retains IDs, output references, and compaction relations, but not the full checkpoint or canonical item array. `codexTransferSource()` supplies both resident and streamed reads after the caller resolves the exact requested Session. These readers are used by the registered Codex transfer source.
